# Безопасность / Security

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный issue**. Используйте приватный канал GitHub:
**Security → Report a vulnerability** в репозитории
(https://github.com/d3grando/pocket-finance/security/advisories/new). Опишите версию (коммит или
тег), шаги воспроизведения и что именно удаётся получить. Мы ответим в течение нескольких дней и
договоримся о сроках исправления и публикации.

Please report vulnerabilities privately via GitHub's *Report a vulnerability* (Security tab), not
in public issues.

Поддерживается последняя версия из ветки `main` / последний релиз.

## Модель угроз

Pocket Finance — **self-hosted** приложение для одного человека или семьи. Предполагается:

- сервер и его `.env` контролирует тот, кто установил Pocket; пользователи одной установки
  доверяют друг другу (это не мульти-тенантный SaaS);
- наружу смотрит только порт `web` (за вашим reverse-proxy или встроенным Caddy с HTTPS);
  API, база и бэкапы не публикуются, база — во внутренней сети compose без выхода в интернет;
- AI-провайдер выбираете вы: тексты фраз, которые не разобрал встроенный парсер, и краткий
  контекст (названия счетов, категорий, продавцов, людей в долгах — без сумм) уходят в
  `AI_BASE_URL`. С `AI_ENABLED=false` к AI-провайдеру ничего не уходит.

### Исходящие соединения

Сервер сам ходит только сюда (данные пользователя — только в AI и Telegram):

| Куда | Кто | Что уходит |
|---|---|---|
| `AI_BASE_URL` | `api` | фразы и краткий контекст (см. выше); выключается `AI_ENABLED=false` |
| `api.telegram.org` | `bot` | сообщения бота; только если задан `TELEGRAM_BOT_TOKEN` |
| `www.vietcombank.com.vn`, `www.cbr.ru`, `www.cbr-xml-daily.ru`, `api.coingecko.com`, `open.er-api.com` | `worker`, `api` | только запросы курсов (дата, коды валют), без данных пользователя |
| `BACKUP_REMOTE` | `backup` | дампы базы; только если задан |
| Let's Encrypt (ACME) | `caddy` | получение сертификата; только профиль `standalone` |

## Что сделано

- Пароли — argon2id; вход ограничен по IP и общим бакетом неудачных попыток.
- Веб: cookie-сессии `HttpOnly`/`Secure`/`SameSite`, CSRF-токен на изменяющих запросах,
  идемпотентность записей (`Idempotency-Key`), строгий CSP и заголовки безопасности (Caddy).
- Passkeys / Face ID (WebAuthn, `userVerification=required`). Добавление ключа требует пароль
  (кроме только что созданной сессии), о новом ключе приходит сообщение в Telegram; «Выйти
  везде» и смена пароля по умолчанию удаляют все ключи.
- Electron: `contextIsolation`, sandbox, без Node в рендерере, fuses (запрет `RUN_AS_NODE`,
  проверка целостности `app.asar`), внешние ссылки — только https и только разрешённые хосты,
  опасные IPC — только из окон настроек/входа, токен устройства — в `safeStorage` (DPAPI).
- Бот отвечает только Telegram id из `TELEGRAM_ALLOWED_IDS` (пусто = никому); бот ходит в API
  с сервисным токеном.
- Логи без текста операций и без полных идентификаторов (длина и короткий хэш).
- Контейнеры `api`, `worker`, `bot`, `web` — `cap_drop: ALL`, `no-new-privileges`, read-only
  корневая ФС; `backup` и `caddy` — только нужные capabilities и лимиты памяти/процессов (для
  остальных лимиты можно добавить в `docker-compose.override.yml` под своё железо); в
  `prod` api не стартует без `SECRET_KEY`, https-адреса в `PUBLIC_URL` и настроек AI.

## Известные ограничения

- **Общий бакет неудачных входов**: 20 неверных паролей в час со всех адресов вместе блокируют
  вход паролем для всех до конца часа (защита от распределённого перебора). Снять: перезапуск
  `api`; порог — `RATE_LIMIT_LOGIN_FAILURES_PER_HOUR` в `.env`, затем `docker compose up -d`. Вход по passkey и уже открытые сессии работают.
- **Привязка Telegram**: в установке на несколько пользователей каждый должен сразу привязать
  свой Telegram id в настройках — свободный id может занять другой пользователь этой установки.
- **Бэкапы не шифруются**: храните `BACKUP_DIR` и удалённую копию на доверенном хосте.
- **`.exe` без подписи**: сверяйте SHA256 из релиза; автообновления нет.
- **AI-журнал**: полный контекст запросов к LLM хранится в базе 180 дней (для отладки и отмены),
  затем удаляется планировщиком.
- **API подключается к PostgreSQL владельцем схемы**: отдельная роль с минимальными правами —
  в планах.
- `/passkeys/login/options` по логину показывает, есть ли у него ключи.
- Абсолютного срока жизни сессии нет: 90 дней скольжения; отзыв — «Выйти везде».
- Сервисный токен бота принимается с любого адреса внутренней сети compose.
