# Pocket Finance — фича «Долги» (DEBTS)

> Архитектура и контракт фичи. Ключевые решения (п.1–10 ниже) важнее остального текста.
> Код: миграция `0005`, модели, схемы (`app/schemas/debts.py`, добавки в `intents.py`/`assistant.py`/
> `transactions.py`/`settings.py`/`accounts.py`), сервис `app/services/debts/*`, `app/api/routes/debts.py`,
> общий модуль имён `app/core/person_names.py`.
> Менять контракт — только аддитивно.

## 0. Ключевые решения (кратко)
1. Долг — не расход и не доход. «дал в долг Коле 500к» → −500к с Карта, Коля должен 500к; «Коля вернул 200к» → +200к на Карта, остаток 300к; «занял у Пети 1м» → +1м, я должен Пете 1м; «отдал Пете 500к» при долге Пете → −500к со счёта, мой долг 500к.
2. Списки «Мне должны» / «Я должен» с остатком по человеку: главная (если есть открытые), «Счета» → блок «Долги», бот `/debts`. Карточка человека — история займов и возвратов.
3. Частичные возвраты; любая валюта, включая крипту, без пересчёта; остатки по валютам отдельно, ≈ $ рядом.
4. Напоминание по желанию (по умолчанию ВЫКЛ, N = 30): «Коля должен 300 000 ₫ уже 30 дней» + [Записать возврат] [Напомнить позже].
5. Неоднозначности: «X вернул N» без «долг» — возврат, если у X открытый долг передо мной в этой валюте, иначе доход; «отдал X N» — погашение, если я должен X, иначе расход «Переводы людям». Переплата — без потери денег и без выдумывания.
6. «Коля не вернёт» / «простить долг Коле» / «списать долг Коли» → остаток становится расходом «Переводы людям» (личное), сразу + отмена.
7. Счёт — по общим правилам (₫ → Карта, «налом» → Наличные, крипта/$ без счёта → сохранить и спросить кнопками).
8. Долги не входят в доходы/расходы и «чистый поток»; на главной отдельные «Мне должны ≈ / Я должен ≈».
9. Совместимость с клиентами без поддержки долгов (ранее собранный Electron с упакованным вебом, сторонние клиенты API): ответы ассистента — через существующие карточки (title/subtitle/кнопки «Отменить»/«Изменить»), новые поля — только аддитивно. Миграция — только аддитивная. Старые операции не трогаем.
10. Отмена/правка — как у остальных (undo по action id, «нет, 250к»).

## 1. Выбранная модель: «долг = служебный счёт человека»
- На каждого человека — строка `debts` + служебный счёт `accounts.kind='debt'`, мультиактивный, имя `«Долг: Коля»`, иконка `HandCoins`. По каждой валюте строка `account_assets` с `opening_balance = 0`, `opening_at = NULL` → **баланс всегда известен** (все проводки считаются, задним числом тоже).
- **Баланс долга = баланс этого счёта по активу.** Знак: `> 0` — человек должен мне (дебиторка), `< 0` — я должен человеку. Валюты не смешиваются и не пересчитываются.
- Займы и возвраты — **обычные переводы** (`kind='transfer'`) между реальным счётом и счётом-долгом: переводы уже исключены из доходов/расходов (ARCH §4.2), значит п.8 выполняется без правок статистики. Прощение — **расход/доход** на счёте-долге (п.6 прямо требует расход).
- Почему не новые `kind`: клиент без поддержки долгов знает только 6 видов операций; `transfer` он рисует как «Перевод Карта → Долг: Коля» — понятно и без обновления. Новые виды сломали бы иконки/фильтры/формы такого клиента.
- Почему не «остаток считать из истории без счёта»: проводки, блокировки (`lock_assets`), undo, «Разобрать», правка суммы — уже работают на уровне счетов; служебный счёт переиспользует всё это. Нетто по человеку (занял у Пети, когда Петя мне должен) получается само.
- Пометка операции — новая колонка `transactions.debt_op` (`lend|repay_in|borrow|repay_out|forgive`), у всех старых строк `NULL`. Нужна для подписей, истории и правил правки (направление перевода по одним проводкам неотличимо: «дал в долг» и «вернул свой долг» двигают деньги одинаково).

## 2. Где служебные счета НЕ видны
Счета `kind='debt'` исключаются из: `GET /accounts` и `/accounts/balances` (новый query `include_debts=false` по умолчанию; итоги `total_vnd/usd` их не включают), `accounts.service.list_accounts/resolve_account/default_account_for`, `ParseContext.accounts` (`ai/context.py`), вариантов «С какого?» (`dispatcher.account_options` — следует из контекста), ответа «остатки» (`stats/balances.py`), поиска (`stats/search.py`, хиты `account`), онбординга, форм переводов. `_body_account` (ручные `POST /transactions`, `/transfers`, `/exchanges`, `/adjustments`, `PUT /accounts/{id}/opening`, `PATCH/DELETE /accounts/{id}`) на счёт-долг → 422 «Это счёт долга — используйте «Долги»». Писать в счёт-долг может только `services/debts`.

## 3. Данные и миграция `0005` (аддитивная)
**debts**: `id BIGINT PK`, `user_id FK CASCADE`, `account_id FK accounts ON DELETE CASCADE UNIQUE`, `name VARCHAR(64)` (отображаемое, именительный по возможности, ≤ 56 символов), `name_key VARCHAR(64)` (`person_names.name_key`), `aliases TEXT[]` (встреченные формы: «коле», «у коли»), `handle CITEXT NULL` (без @), `note TEXT NULL`, `is_archived BOOL DEFAULT false`, `remind_snoozed_until DATE NULL`, `last_reminded_on DATE NULL`, `version INT DEFAULT 1`, `created_at`, `updated_at`. UNIQUE `(user_id, lower(name))`, UNIQUE `(user_id, handle) WHERE handle IS NOT NULL`, индекс `(user_id, name_key)`, GIN `(aliases)`.

**transactions**: `+ debt_op VARCHAR(12) NULL` + CHECK значений. CHECK `needs_account_no_account` расширен: `status <> 'needs_account' OR account_id IS NULL OR debt_op IN ('repay_in','borrow')` (см. ориентацию ниже).

**user_settings**: `+ debt_reminders_enabled BOOL DEFAULT false`, `+ debt_reminder_days SMALLINT DEFAULT 30` (CHECK 1..365).

**CHECK расширены**: `accounts.kind` += `debt`; `action_log.kind` += `debt`; `notifications_outbox.kind` += `debt_reminder`. `audit_logs.entity_type` (без CHECK) += `debt`.
SSE-сущность `debts` (старые клиенты неизвестные сущности игнорируют).

Проверено: `alembic upgrade head` с нуля = ORM (тест `test_migrations`), downgrade до base; копия базы на схеме 0004 (около 900 операций) 0004 → 0005: данные целы, `debt_op` у всех NULL, дифф схемы с моделями пуст, 0005 → 0004 → 0005 проходит. Downgrade 0005 отказывается, если есть долговые данные.

### 3.1 Ориентация операций (`transactions`)
| debt_op | kind | `account_id` (источник) | `counter_account_id` (получатель) | баланс долга |
|---|---|---|---|---|
| `lend` дал в долг | transfer | реальный счёт / NULL | счёт-долг | `+amount` |
| `repay_out` я вернул | transfer | реальный счёт / NULL | счёт-долг | `+amount` |
| `repay_in` мне вернули | transfer | счёт-долг | реальный счёт / NULL | `−amount` |
| `borrow` занял | transfer | счёт-долг | реальный счёт / NULL | `−amount` |
| `forgive` при балансе > 0 | expense «Переводы людям» | счёт-долг | — | `−amount` |
| `forgive` при балансе < 0 | income «Прочее» (личное) | счёт-долг | — | `+amount` |

- `amount/currency` — как написал пользователь; сторона счёта-долга всегда в `currency` (1:1).
- Реальная сторона в другой фиатной валюте (долг в $, счёт Карта в ₫) — пересчёт ≈ по курсу как в `apply_account` (`is_estimated=true`): для оттока — `account_amount/account_asset/account_rate`, для притока — `counter_amount/counter_asset`. Крипта с одновалютного счёта — 422 (как у обычных операций).
- **NULL реальной стороны**: `status='needs_account'` (ждём «С какого?/На какой счёт?») или `posted` («Без счёта»). В обоих случаях проводка по счёту-долгу **есть** (долг существует сразу), нет только реальной. Правка `ledger.postings.postings_for`: ранний `return []` для `needs_account` — только если `debt_op IS NULL`; для долговых строк стороны с NULL-счётом просто пропускаются (код уже так делает для transfer).
- `counterparty` = имя человека (поиск в «Операциях» находит «Коля»), `description` — как написал.
- Сводные `amount_usd/amount_vnd` считаются как у всех (`apply_valuation`), в статистику переводы не попадают; прощение попадает (это и есть п.6).

## 4. Семантика операций (`services/debts.record_op`)
Одна долговая операция = одна транзакция + одно действие `action_log.kind='debt'` (undo, контекст «нет, 250к», идемпотентность — как у всех). `summary` действия: «Долг: Коля +500 000 ₫» / «Возврат: Коля −200 000 ₫».
- **Выдать** `lend`: перевод реальный → долг. Если я был должен человеку — нетто (баланс просто растёт), отдельной логики нет.
- **Вернуть частично/полностью** `repay_in`: перевод долг → реальный. `amount=None` → весь остаток в `currency` (остатка нет → 422 «Коля тебе ничего не должен в ₫»).
- **Переплата** (`repay_in` больше остатка): записывается **одна** операция на всю сумму — деньги на счёте верные, ничего не теряется. Баланс уходит в минус = «теперь я должен Коле излишек» (буквально так и есть: он отдал больше, чем был должен). `DebtOpResult.excess` = излишек; карточка помечает его и предлагает кнопку «Излишек — мне» (`send_text` «списать мой долг: Коля 100к» — направление и сумма в тексте), которая прощает обратный долг → доход «Прочее». Симметрично для `repay_out` сверх моего долга: человек становится должен мне излишек, кнопка «Излишек — расход» («простить долг: Коля 100к» → расход «Переводы людям»). Устаревшая кнопка, нажатая после новых операций, не прощает чужое: несовпадение направления или сумма больше остатка → отказ. Правка суммы/отмена пересчитывают всё сами (баланс производный).
- **Занять** `borrow`: перевод долг → реальный. **Погасить** `repay_out`: реальный → долг (`amount=None` → весь мой долг).
- **Простить/списать** `forgive`: направление — по знаку баланса в `currency` (если `direction` задан и не совпадает со знаком → 422). Баланс > 0 → расход «Переводы людям» (личное) на счёте-долге; < 0 → доход «Прочее» (личное). `amount=None` → весь остаток; больше остатка → 422. **Лимит прощения проверяется на каждом пути** (запись, правка суммы/даты прощения, правка/отмена/восстановление других операций этого человека): изменение, после которого какое-то прощение оказывается больше долга на свою дату, → 422; изменения, возвращающие баланс назад (например, отмена ошибочного прощения), не блокируются. Некорректные состояния, записанные до появления этой проверки, сами не чинятся — исправляются отменой лишнего прощения. Баланса в валюте нет → 422 «Долга нет». Несколько валют открыто и валюта не названа → `clarify` (варианты — по валютам).
- **Человек**: `debt_id` или `person_name` → `get_or_create_debt` (поиск по handle → алиасам → `same_person(name_key)`; несколько совпадений → ошибка `ambiguous_target` с вариантами). Новая форма имени запоминается в `aliases`. Архивный человек разархивируется. Undo операции человека не удаляет (пустые люди скрыты из списков, `DELETE /debts/{id}` удаляет человека без операций).
- **Правка** (`update_transaction` для строк с `debt_op`):
  - transfer: `amount`, `currency`, `occurred_on`, `description` + `account_id/account_none` = **реальная** сторона (источник для lend/repay_out, получатель для repay_in/borrow; `needs_account` → `posted`); пересчёт реальной стороны с конвертацией (не `account_amount = counter_amount = amount`, как у переводов в одной валюте); `account_amount` — факт по реальной стороне.
  - forgive: `amount` (≤ остатка до операции), `occurred_on`, `description`, `category_id` (того же вида). Смена счёта/вида → 422.
  - `assign_account` (кнопка «С какого?», в том числе из клиента без поддержки долгов): для долговых transfer ставит реальную сторону (у обычных операций — только для расхода). Сторона по `debt_op` (приток → `counter_account_id`).
  - Смена человека — нет (отмена + новая запись).
- Блокировки: `writer_lock` + `lock_assets` по (счёт-долг, валюта) `FOR UPDATE` при чтении остатка для `amount=None`/переплаты/прощения — гонка двух возвратов не даёт двойного прощения.
- Событие SSE: `transactions`, `accounts`, `debts` (+ `stats` автоматически).

## 5. Ввод: интенты, правила парсера, неоднозначности
### 5.1 Интенты (`schemas/intents.py`, общие для парсера и LLM)
- `DebtIntent {type:"debt", op, person, person_name?, amount?, amount_raw?, currency?, account_ref?, account_none, direction?, fallback?, category_ref?, description?, occurred_on?, occurred_time?}`; `op ∈ lend|repay_in|borrow|repay_out|repay|forgive` (`repay` — направление по балансу, для канонических текстов кнопок).
- `DebtsQueryIntent {type:"debts_query", person?, direction?}` — «кто мне должен?», «мои долги», «сколько должен Коля?».
- `ParseContext.debts: CtxDebt[] {id, name, name_key, aliases, handle, open:[{currency, direction}]}` — **без сумм**.

### 5.2 Детерминированный парсер (частые фразы; флаг `debt` больше не уводит их в LLM)
`<N>` — сумма по общим правилам (к/м, голое < 1000 ₫ = тысячи, валюты/монеты), `<X>` — имя/ник, счёт («с кошелька», «налом», «на карту») и дата («вчера») — как у обычных операций, в любом порядке.
| фраза | интент |
|---|---|
| «дал в долг X N», «дал X в долг N», «одолжил X N», «дал взаймы X N», «X взял в долг N», «lent X N» | `lend` |
| «X вернул долг N», «X вернул N долга», «X отдал долг N», «X погасил долг N» (X — подлежащее, перед глаголом) | `repay_in` |
| «X вернул N», «X отдал N», «X перевёл мне N» (без «долг») | `repay_in` + `fallback:"income"` |
| «X вернул весь долг», «X рассчитался» | `repay_in`, `amount=None` |
| «занял у X N», «взял в долг у X N», «одолжил у X N», «X одолжил мне N», «X дал мне в долг N», «borrowed N from X» | `borrow` |
| «вернул X долг N», «вернул долг X N», «отдал долг X N», «погасил долг X N» (глагол без подлежащего = я) | `repay_out` |
| «отдал X N», «вернул X N» (без «долг») | `repay_out` + `fallback:"expense"` |
| «вернул X весь долг», «рассчитался с X» | `repay_out`, `amount=None` |
| «простить долг X», «простил X долг», «списать долг X/Xа», «X не вернёт», «забудь долг X» | `forgive`, `direction:"owed_to_me"` |
| «X простил мне долг», «X простил долг», «списать мой долг X» | `forgive`, `direction:"i_owe"` |
| канонические (кнопки бота/карточек): «дал в долг: X N», «занял: X N», «возврат долга: X [N]», «списать долг: X [N] [ВАЛЮТА]» | `lend` / `borrow` / `repay` / `forgive` (direction по балансу) |
| канонические с направлением (кнопки излишка): «списать мой долг: X N», «простить долг: X N» | `forgive`, `direction:"i_owe"` / `direction:"owed_to_me"` |
| «кто мне должен», «кому я должен», «мои долги», «долги», «сколько должен X», «/debts» | `debts_query` |
- Отличать от возврата покупки: «вернули 200к за наушники» (нет лица-подлежащего, есть «за …») остаётся `refund`. «X вернул N» — только если X совпал с `ctx.debts` (по `same_person`) **или** X — имя собственное с заглавной/`@ник`, и нет «за <товар>».
- `fallback` по п.5: парсер ставит его, если слова «долг» нет, и **всегда** выдаёт `DebtIntent` + `fallback`: конверсию в обычный интент (`create_transaction` income / expense «Переводы людям», `counterparty=X`) делает валидатор по БД, поэтому заметка «Долга у X нет — записал как доход» есть всегда. «Петя отдал за ужин 300к» (есть «за …») всегда уходит в LLM; без AI — «AI недоступен», а не выдуманный расход.
- Архивные люди не входят в `ctx.debts`: текст кнопки для архивного человека с цифрами в имени идёт старым путём (цифры могут прочитаться как сумма) — редкий случай, известное ограничение.
- Имя: `person` = как написано; `person_name` — `person_names.nominative_guess(form, case)` по конструкции (`дал/отдал/вернул X` → dat, `у X`/`от X` → gen, подлежащее → nom). Известный человек (совпал `name_key`) → `person_name` = его имя. Новый человек с `certain=False` (датив на «-е»: Коле/Лене) → `needs_llm=True, partial_ok=True` (LLM уточнит именительный; без LLM — запись с догадкой, имя правится в карточке человека).
- Две операции в одном сообщении («дал Коле 500к и Пете 200к») — две `DebtIntent`, атомарно.

### 5.3 Имена (`app/core/person_names.py`, готово)
`name_key` (стем по слову, без предлогов «у/от/к», `ё=е`, без `@`), `same_person(a, b)` (равны или отличаются одной буквой хвоста; короткие — только гласной хвоста), `nominative_guess(form, case) → (Имя, certain)`. Один код у парсера, валидатора и `debts.find_debt` — «Коле», «у Коли», «Коля вернул» всегда один человек. Тесты — `tests/debts/test_person_names.py`.

### 5.4 Валидатор и диспетчер
- Валидатор: сумма из `amount_raw` (как везде), валюта (неоднозначная → clarify), человек → `debt_id` (найден) / `new_person_name` (не найден; для `repay*`/`forgive` с неизвестным человеком → `unclear` «Не знаю долгов X»), неоднозначный человек → `unclear ambiguous_target` с вариантами-именами. Решение `fallback` и `repay` — по **БД** (`debts.balances_of`): нет баланса нужного знака в валюте → обычная операция (income: категория из `category_ref` или «Прочее»; expense: «Переводы людям»; `counterparty`=имя).
- Явный возврат («вернул **долг**») без баланса в этой валюте → `unclear`: «У Коли нет долга в ₫ (есть: USDT)» + варианты `send_text`: «Коля вернул 500к» (→ доход по п.5) и по каждой открытой валюте «возврат долга: Коля <остаток> <ВАЛЮТА>». Для `repay_out` — «дал в долг: Коля 500к» и «500к Переводы людям».
- Счёт: `account_ref`/`account_none` → как у операций; иначе дефолт по валюте (₫ → Карта, ₽ → Карта RUB); крипта/$ без счёта → `needs_account`. Для `forgive` счёт не нужен.
- Диспетчер: `debts.record_op(..., action=ctx)` в общей транзакции сообщения; карточка — §8. `debts_query` → `debts.list_debts` → `answer`.
- «нет, 250к», «удали последнюю», «отмени», кнопка «Изменить» — существующие пути (`update_transaction`/`delete_transaction`/`undo`); ledger сам соблюдает правила §4 «Правка». `ActionBrief.tx_kind` для долга = `transfer`/`expense`, `summary` — из действия `debt`.

## 6. Контекст LLM
В промпт идёт блок «Долги» из `ctx.debts`: `Коля (алиасы: коле, коли) — должен мне: VND, USDT`; `Петя — я должен: VND`. **Никаких сумм, дат, истории.** Плюс правила: долг не расход/доход; п.5 (ставь `fallback`, решает сервер); прощение; `person_name` в именительном; несколько валют — не угадывать. Схема ответа — тот же `IntentList` (новые типы уже в union). Бенч: +20 долговых фраз в датасет (`backend/bench/`), включая крипту, «налом», переплату, неоднозначности п.5, «не вернёт».

## 8. Карточки ассистента (обратно совместимые)
Только существующие `kind` и кнопки (`undo`, `edit`, `choose_account`, `later`, `send_text`, `open`). Новое — необязательное поле `debt: DebtBrief {debt_id, name, op, currency, balance_after, excess}` у `created`/`needs_account`/`updated` и `debts: DebtsOut` у `answer`. Имя всегда в именительном после двоеточия — без склонений и без рода: «Коля: долг тебе 500 000 ₫» (не «Коля должен» — имя на -а/-я может быть и Маша). Бот и веб строят свои строки так же.

## 9. Напоминания (планировщик + кнопки бота)
- Настройки: `debt_reminders_enabled` (ВЫКЛ по умолчанию), `debt_reminder_days` = N (30).
- Задача воркера `debt_reminders` (`services/debts/reminders.enqueue_debt_reminders`, подключена в `scheduler/jobs.py`, каждый тик): пользователи с включённой настройкой, локальное время ≥ 10:00; по каждому неархивному человеку с ненулевым балансом: возраст = `today − open_since` (дата, с которой текущий баланс того же знака стал ненулевым; частичные возвраты возраст не сбрасывают, обнуление и новый займ — сбрасывают). Условие: возраст ≥ N, `remind_snoozed_until` пуст или ≤ today, `last_reminded_on` пуст или ≤ today − N (повтор раз в N дней). Одно сообщение на человека (все валюты), outbox `kind=debt_reminder`, `dedupe_key=debt_reminder:{debt_id}:{YYYY-MM-DD}`, затем `last_reminded_on=today`.
- Текст (HTML, экранировать имя): «⏰ Коля должен 300 000 ₫ уже 30 дней» (несколько валют: «300 000 ₫ и 50 USDT»); для «я должен»: «⏰ Твой долг · Петя: 1 000 000 ₫ уже 30 дней».
- Кнопки (`payload.buttons`): `[{"text":"Записать возврат","callback":"dr:{debt_id}"}, {"text":"Напомнить позже","callback":"dz:{debt_id}"}]`.
- Бот: `dr:` → «Сколько вернул Коля? Напиши сумму (например 200к)» + кнопка «Весь долг» (`dra:{debt_id}`); ответ текстом → `POST /assistant/messages` с текстом «возврат долга: Коля <текст>» (бот берёт имя из `GET /debts/{id}`), `dra:` → «возврат долга: Коля». Карточка ответа — обычная (`created`/`needs_account`). `dz:` → `POST /debts/{id}/snooze {days:7}` → «Напомню через 7 дней». Ключи идемпотентности — `tgcb:{callback_id}` / `tg:{chat}:{msg}`, как у остальных кнопок бота.

## 10. Веб (клиентам без поддержки долгов ничего из этого не нужно)
- Типы и хуки: `DebtsOut`, `DebtDetailOut`, `DebtOpCreate/Result`, `DebtPatch`, `TxDebtRef` (`TransactionOut.debt?`), `DebtBrief` (`card.debt?`), settings `debt_*`; query-ключи `['debts']`, `['debt', id]`; SSE `debts` → `['debts']`, `['debt']` (+ `transactions` тоже инвалидирует долги).
- **Главная**: если `owed_to_me` или `i_owe` не пусты — блок «Долги»: две цифры «Мне должны ≈ X ₫» / «Я должен ≈ Y ₫» (`totals`, ₫ по `summary_currency`, ≈ $ мелко), до 3 человек в каждом столбце, «Все →» `/accounts?debt=all`. Пусто — блока нет. В KPI «Доходы/Расходы/Поток» долги не входят (сервер так и считает).
- **Счета** → отдельный блок «Долги» под счетами (не в общем итоге): два списка с остатком по каждой валюте (`300 000 ₫ · 50 USDT ≈ $50`), возраст «30 дн.», кнопки «Дать в долг», «Занять» (форма `POST /debts/operations`: человек с автодополнением по `/debts?include_settled=true`, сумма, валюта, счёт, дата).
- **Карточка человека** (sheet/диалог по `/accounts?debt=<id>`): остатки по валютам, история (`DebtHistoryItem`: дата, «Дал в долг»/«Возврат»/«Занял»/«Вернул долг»/«Списан», сумма со знаком, остаток после), действия «Записать возврат» (частично / «весь долг»), «Простить остаток» (подтверждение), «Переименовать», «Архивировать» (только при нулевом балансе), отмена последней операции через `undo`.
- **Операции**: строки с `tx.debt` — иконка `HandCoins`, заголовок «Дал в долг: Коля» и т.п., клик по имени открывает карточку. Фильтр по виду не меняется (это `transfer`).
- **Quick/ассистент**: карточки рендерятся как обычно; если есть `card.debt` — строка «Коля должен 300 000 ₫» и для `excess` — подсветка излишка. Кнопка «Излишек — мне» приходит обычным `send_text`.
- **Настройки** → «Telegram» (отчёты, напоминания, бот): тумблер «Напоминать о долгах», поле «старше N дней» (1–365), `PATCH /settings` с `version`.

## 12. Аналитика
- Доходы/расходы/поток/категории/топ/сравнение/бизнес: без изменений — долговые переводы туда не попадают по построению (`PNL_KINDS`). Прощение — обычный расход/доход (п.6).
- «Разобрать: N» включает долговые операции, ждущие счёта (они `needs_account`) — это правильно.
- Остатки/итог по счетам — без счетов-долгов (§2). Сводка долгов — `GET /debts.totals` (главная), ≈ по текущему курсу.
- Месячный отчёт (по желанию): строка «Долги: мне должны ≈ X, я должен ≈ Y», если не ноль.
- Экспорт: CSV — без изменений (переводы с получателем «Долг: Коля»); `/export/full` — `+ debts[]` (аддитивно). `wipe` — счета-долги удаляются вместе со счетами (FK CASCADE на `debts`).

## 15. Заметки реализации
- Напоминания — отдельная задача воркера `debt_reminders` (каждый тик), не внутри `recurring_reminders`.
- `/export/full` — `+ debts[]` верхнего уровня; люди дополнительно вложены в `accounts[].debt` (оба аддитивны).
- `DebtOpCreate.direction` (аддитивно): для `forgive` сервер перепроверяет направление под блокировкой (422 `reason=direction`); ассистент передаёт `DebtIntent.direction`.
- Сводки действий долга (undo «Отменено: …») — единые у REST и ассистента, знак = изменение долга «X должен мне»: «Долг: Коля +500 000 ₫», «Возврат: Коля −200 000 ₫», «Занял: Петя −1 000 000 ₫», «Вернул долг: Петя +500 000 ₫», «Списан долг: Коля −300 000 ₫», «Долг прощён: Коля +100 000 ₫».
- Мерчант не может ссылаться на счёт-долг как `default_account_id` (422).
- парсер всегда выдаёт `DebtIntent` с `fallback` (§5.2), заметка о конверсии есть всегда.
- `DebtDetailOut.last_action_id` (аддитивно) — новейшее действующее действие над последней операцией (создание или последняя правка); веб отменяет его сразу, с сервером без этого поля — обход через `GET /transactions/{id}/history` + `GET /actions`.
- Лимит прощения — на каждом пути (§4). Ранее записанные некорректные состояния не чинятся автоматически; отмена лишнего прощения работает.
- Поиск (`/search`, `/transactions?q=`): долговые операции находятся и по **текущему** имени/алиасу/@нику человека (после переименования), заголовки — с текущим именем; по старому тексту `counterparty` — тоже.
- Кнопки излишка с направлением и суммой: «списать мой долг: X N» / «простить долг: X N» (§4, §5.2, §8).
- Тексты без рода «X: долг тебе N» — в бэкенде, боте (`fmt.debt_state`, карточка человека, подсказка возврата) и вебе (`debtBriefLine`, `balanceDirectionText`, диалог прощения «Простить долг: X?» / «Закрыть мой долг: X?»). Текст напоминания (п.4) — без изменений.
- Ответ про одного человека: `debts.totals` только по нему (`services/debts/totals.totals_of`).
- Веб: тосты кликабельны поверх модалок, клик по тосту не закрывает ни `operations/ui/overlays`, ни shadcn `components/ui` (dialog/sheet/drawer) — `lib/keep-open-on-toast`.
- Дедуп списка изменений у `updated`-карточек — для всех `updated`, не только долговых (намеренно).
- Известно: у `UpdatedCard` нет `note` (текст излишка при правке — в `subtitle`); при желании — аддитивное поле в `schemas/assistant.py`.
