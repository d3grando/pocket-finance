# Обновление Pocket Finance

## Обычное обновление

```bash
cd /opt/pocket
scripts/update.sh
```

Что делает скрипт:

1. **Делает бэкап базы** (`pf-backup run`) — пока ещё ничего не изменено. Если бэкап не
   удался, обновление останавливается: код, `.env` и контейнеры остаются как были.
2. Проверяет, что в рабочей копии нет локальных правок (`git status`), делает `git fetch`,
   переходит на ветку по умолчанию (`main`; если рабочая копия осталась на коммите после
   прошлого `--ref`, скрипт сам переключится обратно) и делает `git pull --ff-only`.
3. Записывает версию (`git describe`) в `PF_VERSION` в `.env` — это тег образов и поле
   `version` в `/api/v1/health`.
4. Собирает образы с обновлением базовых (`docker compose build --pull`).
   Если сборка (или git) упали — код и `PF_VERSION` возвращаются на прежние, работающие
   контейнеры не тронуты.
5. `docker compose up -d --remove-orphans` — пересоздаёт изменившиеся контейнеры.
   Контейнер `api` при старте выполняет `alembic upgrade head` (миграции; каждая применённая
   ревизия видна в `docker compose logs api`), `worker` и `bot` стартуют после того, как `api`
   стал healthy.
6. Ждёт `healthy` у `api` и `web`, печатает health и имя бэкапа, сделанного перед
   обновлением. Удаляет образы проекта старых версий: остаются только текущая и предыдущая
   (для отката).

Флаги:

| Флаг | Смысл |
|---|---|
| `--ref v1.2.0` | перейти на тег/ветку/коммит (откат). Следующий запуск без `--ref` вернёт на `main` |
| `--restore daily/<дамп>` | после сборки вернуть базу из дампа (откат со старой схемой БД, см. «Откат») |
| `--no-pull` | не трогать git (например, код уже обновлён вручную) |
| `--no-backup` | не делать бэкап перед обновлением (не рекомендуется) |

Простой во время обновления — секунды: пока `api` перезапускается, веб отвечает на `/api`
JSON-ошибкой `service_unavailable`, клиенты повторяют запрос; статика и PWA работают.

## Вручную (то же самое по шагам)

```bash
scripts/backup.sh
git checkout main && git pull --ff-only
docker compose build --pull
docker compose up -d --remove-orphans
docker compose ps
curl -s http://127.0.0.1:8080/api/v1/health
```

## Миграции базы

- По умолчанию миграции применяются автоматически при старте `api`
  (`MIGRATE_ON_START=true`). Ошибка миграции = `api` не стартует (видно в
  `docker compose logs api`), старая база не повреждена — Alembic выполняет миграцию в
  транзакции.
- Вручную: `MIGRATE_ON_START=false` в `.env`, затем
  `docker compose run --rm api migrate` и `docker compose up -d`.
- Текущая ревизия: `docker compose exec api pf-entrypoint alembic current`.

## Откат

Предыдущая версия — значение `PF_VERSION` до обновления (`update.sh` печатает «версия: X
(была Y)»; его образы не удаляются) или нужный тег/коммит из `git log`. Имя бэкапа, сделанного
перед обновлением, `update.sh` печатает в конце («бэкап перед обновлением: daily/…»); список —
`scripts/backup.sh list`.

**Новая версия не добавляла миграций** (в `docker compose logs api` при её запуске не было
строк `Running upgrade`):

```bash
scripts/update.sh --ref <предыдущая версия>
```

**Новая версия добавила миграцию** — старый код на такой базе **не запустится**: Alembic не
знает новую ревизию, `api` перезапускается в цикле и пишет «База данных уже обновлена более
новой версией Pocket …». Так бывает при **любой** новой миграции, а не только при
«несовместимой». Способы:

1. **Вернуть базу из бэкапа перед обновлением** (всё, что записано после обновления, пропадёт;
   текущая база сохранится в `pre-restore/`):
   ```bash
   scripts/update.sh --ref <предыдущая версия> --restore daily/pocket_<дата>_<время>.dump
   ```
   Скрипт соберёт старые образы, остановит `api`/`worker`/`bot`, восстановит дамп и запустит
   старую версию. Если `update.sh --ref …` уже запущен без `--restore` и упал на
   «перезапускается в цикле» — просто `scripts/restore.sh --yes daily/pocket_<…>.dump`.
2. **Откатить миграции новым кодом, сохранив данные** (если у миграций есть `downgrade`) —
   пока работает новая версия:
   ```bash
   prev=<предыдущая версия>
   rev=$(docker run --rm --entrypoint alembic pocket-backend:$prev heads | awk '{print $1}')
   docker compose exec api pf-entrypoint alembic downgrade "$rev"
   scripts/update.sh --ref "$prev"
   ```
   (`pocket-` — `PF_IMAGE_PREFIX`, если вы его меняли.)

3. **Временный обход, без отката базы**: `MIGRATE_ON_START=false` в `.env`, затем
   `scripts/update.sh --ref <предыдущая версия>` — старый код стартует на новой схеме без
   миграций. Годится, только если миграция лишь добавила таблицы или столбцы с умолчанием;
   иначе старый код будет падать на записи. После возврата на новую версию верните
   `MIGRATE_ON_START=true`.

**Вернуться на свежую версию** после отката: `scripts/update.sh` (без `--ref` он сам
переключится на `main`; `--ref main` тоже работает).

Подробно о восстановлении — `docs/BACKUP.md`.

## Смена отдельных настроек

| Что поменять | Команда |
|---|---|
| `.env` (AI-модель, ключи, origin'ы) | `docker compose up -d` |
| `WEB_API_BASE_URL` (вшит в сборку) | `docker compose up -d --build web` |
| Расписание/ротация бэкапов | `docker compose up -d backup` |
| Модель AI (бенч выбрал другую) | `AI_MODEL=…` в `.env` → `docker compose up -d api worker` |

## Обновление Electron и PWA

- **PWA** не перезагружается сама под руками: после выката открытое приложение показывает
  «Доступна новая версия · Обновить» и применяет её само, только когда это безопасно —
  приложение ушло в фон, в строке ввода пусто и нет открытого диалога (черновик строки
  сохраняется). Сервис-воркер и `index.html` отдаются с `Cache-Control: no-cache`, поэтому
  новая версия видна при следующем открытии.
- **Electron** — установите новый `Pocket-Setup-<версия>.exe` поверх старого (без удаления):
  вход (токен устройства), хоткей и настройки сохраняются. Веб-часть мини-окна и «Полной
  панели» вшита в `.exe`, поэтому изменения веба доходят до Electron только с новым
  установщиком; совместимость с сервером держится контрактом `/api/v1`. Где взять `.exe` —
  `docs/INSTALL.md` §7 (артефакт CI `pocket-windows` или релизный файл с `.sha256`).

## Версии и теги

- Релиз = тег `vX.Y.Z` на `main` (первый — `v1.0.0`). Номер версии одинаковый во всех
  пакетах: `backend/pyproject.toml`, `bot/pyproject.toml`, `web/package.json`,
  `desktop/package.json` (из него имя `Pocket-Setup-X.Y.Z.exe`), `app_version` в
  `backend/app/config.py`, `PF_VERSION` в `.env.example` и `docker-compose.yml`.
- `update.sh` пишет в `PF_VERSION` результат `git describe --tags` (на теге — `v1.0.0`, после
  него — `v1.0.0-3-g<коммит>`); это же значение отдаёт `/api/v1/health` в поле `version`.
- Встать ровно на релиз: `scripts/update.sh --ref v1.0.0`.

## Обслуживание Docker

```bash
docker compose logs --tail 200 api     # логи (ротация 20 МБ × 5 на контейнер)
docker system df                       # место под образы/тома
docker builder prune -f --filter until=168h   # старый кэш сборки
```

`update.sh` сам удаляет образы проекта старше предыдущей версии; кэш сборки (`docker builder`)
чистите вручную раз в несколько месяцев.

Тома `*_pgdata` и `*_caddy_data` не удаляйте: `docker compose down -v` **уничтожит базу**
(используйте просто `docker compose down`).
