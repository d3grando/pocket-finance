## 0. Принципы

Pocket — это не админка с таблицами, а инструмент, который пользуется словами вместо форм. Пять правил, которыми проверяется каждый экран:

1. **Ввод важнее всего.** На каждом экране, где можно записать операцию, AI-строка видна без прокрутки и получает фокус по `Ctrl+K`. От нажатия хоткея до записи — меньше 3 секунд и ноль кликов мышью.
2. **Только правда о деньгах.** Нет остатка — нет цифры (пишем «остаток не задан», а не «0 ₫»). Не говорим «сохранено», пока сервер не ответил `2xx`. Пересчитанные суммы всегда с «≈».
3. **Тихий интерфейс, громкие цифры.** Хром (рамки, фоны, подписи) — нейтральный и приглушённый. Цвет тратим только на смысл: доход, расход, перевод, ошибка, «требует внимания». Акцентный фиолетовый — только для фокуса, основного действия и выделения.
4. **Каждое действие обратимо на месте.** Под результатом всегда «Отменить» и «Изменить», без модалок. Подтверждение (превью + Enter) — только для массовых изменений и правок по поиску.
5. **Плотно, но не тесно.** Как Linear: 13–14 px основной текст, строки по 40–44 px, много воздуха между блоками, мало воздуха внутри строк. Сумма всегда выровнена по правому краю и табличными цифрами.

Антипаттерны, которых не делаем: карточки с тенью на каждом блоке, градиенты на графиках, красный цвет на каждой трате (трата — нормальное событие, не ошибка), спиннеры на весь экран, модальные «Вы уверены?», тосты «Успешно!» без содержания, эмодзи в веб-интерфейсе (кроме 🆕 у новой категории — осознанное исключение).

## 1. Цвет: токены

### 1.1. Модель

- Пространство — **OKLCH** (родное для Tailwind 4 и нового shadcn/ui). Для каждого цвета в таблице дан hex-эквивалент (для Electron-трея, Telegram-картинок, PNG).
- Имена совпадают с shadcn/ui (`--background`, `--foreground`, `--card`, `--primary`, `--muted`, `--border`, `--ring`, `--chart-1..5`, `--sidebar-*`), поэтому компоненты shadcn работают без правок. Свои токены добавлены рядом: `--surface-2`, `--subtle-foreground`, `--expense`, `--income`, `--transfer`, `--warning`, `--success`, `--chart-6..8`, мягкие фоны `*-soft`.
- Тема переключается классом `.dark` на `<html>` (стандарт shadcn). Режим «Как в системе» по умолчанию: скрипт в `<head>` до отрисовки ставит класс по `prefers-color-scheme` и выбору в настройках (localStorage `pf.theme` = `system|light|dark`, чтение в try/catch).
- Базовый оттенок нейтралей — холодный 265° с очень низкой хромой: интерфейс выглядит «чернильным», а не серым.

### 1.3. Правила применения цвета

| Что | Токен | Пример |
|---|---|---|
| Сумма расхода в списке | `text-foreground` + знак «−» | `−150 000 ₫` чёрным, не красным |
| Сумма дохода | `text-income` + «+» | `+300 USDT` |
| Перевод/обмен | `text-transfer`, иконка `ArrowLeftRight` | `3 TON · Кошелёк → Копилка` |
| KPI «Расходы сегодня/месяц» | `text-foreground`, маленькая точка `bg-expense` у подписи | |
| KPI «Доходы» | `text-foreground`, точка `bg-income` | |
| KPI «Денежный поток» | `text-income` при ≥ 0, `text-expense` при < 0 | `+4 200 000 ₫` |
| Чип «🆕 новая категория» | `bg-primary-soft text-primary` | |
| Бейдж «Разобрать: 2» | `bg-warning-soft text-warning` | |
| Ошибка валидации/сети | `text-destructive`, фон `bg-expense-soft` | |
| Фокус | `ring-2 ring-ring/40` + `--shadow-focus` | |
| Отрицательная разница в сравнении периодов | расход вырос → `text-expense`, упал → `text-income` | «+18% к сентябрю» |

Цвет никогда не единственный носитель смысла: у расхода всегда «−», у дохода «+», у перевода «→», у ошибки — иконка `CircleAlert` и текст.

### 1.4. Проверка контраста (WCAG 2.2 AA)

Посчитано скриптом (OKLCH → sRGB → относительная яркость). Текст: ≥ 4.5:1, крупный текст и графика: ≥ 3:1.

| Пара | Светлая | Тёмная |
|---|---|---|
| foreground / card | 17.9 | 16.2 |
| muted-foreground / card | 6.0 | 7.2 |
| muted-foreground / muted | 5.3 | 6.5 |
| subtle-foreground / card (не для мелкого текста) | 3.9 | 4.9 |
| primary-foreground / primary | 5.95 | 6.9 |
| primary / primary-soft | 5.3 | 5.5 |
| expense / card · / expense-soft | 5.2 · 4.7 | 6.8 · 6.0 |
| income / card · / income-soft | 5.2 · 4.7 | 8.9 · 7.6 |
| transfer / card · / transfer-soft | 5.2 · 4.7 | 7.9 · 6.8 |
| warning / card · / warning-soft | 5.4 · 5.0 | 9.4 · 8.0 |
| destructive / card | 5.4 | 5.7 |
| chart-1…8 / card (графика, ≥ 3:1) | 4.98 · 3.77 · 3.59 · 4.02 · 4.81 · 3.44 · 5.51 · 4.87 | 6.4 · 8.8 · 8.0 · 8.2 · 6.7 · 10.9 · 6.3 · 5.8 |

Граница `--border` намеренно ниже 3:1 (1.3:1) — это декоративный разделитель, не граница элемента управления. У полей ввода и кнопок-контуров граница `--input` + видимый фокус; кликабельность сообщается формой и текстом, не только рамкой.

### 1.5. Палитра графиков

- Категориям цвет назначается **стабильно**: по позиции категории в топ-7 текущего периода → `chart-1…7`, всё остальное сливается в «Прочее» = `chart-8` (slate). Так цвета не «прыгают» между перезагрузками в пределах периода.
- Бизнес/личное на графиках: бизнес = `chart-1` (iris), личное = `chart-2` (teal).
- Доходы vs расходы (динамика): доход = `--income`, расход = `--expense` — исключение из категориальной палитры, это смысловые цвета.
- Соседние сегменты в донат-диаграмме разделяются зазором 2 px цвета `--card` (а не обводкой), поэтому соседние цвета с близкой яркостью (chart-3/chart-6) всё равно различимы.
- Для дальтоников: в легенде всегда подпись + процент; на hover — подсветка сегмента, остальные уходят в 35% непрозрачности.

## 2. Типографика

### 2.1. Шрифт

- **Inter Variable** (OFL, полная кириллица, отличные табличные цифры, оптический размер `opsz` 14–32). Подключается **локально** пакетом `@fontsource-variable/inter` (никаких Google Fonts: PWA и Electron должны работать офлайн и одинаково, плюс внешние CDN нам не нужны). Импорт: `import "@fontsource-variable/inter/opsz.css"` — вариант с осью оптического размера.
- Моно — `@fontsource-variable/jetbrains-mono` только для: исходного текста запроса в истории/аудите, kbd-подсказок, кода восстановления. В суммах моно не используем — табличные цифры Inter выглядят лучше.
- Почему не Geist: у Geist кириллица моложе и уже по начертаниям, а `tnum` в Inter проверен годами в финансовых интерфейсах. Если нужен «более технический» вид — Geist подключается заменой `--font-sans`, остальное не меняется.

### 2.2. Настройки Inter

- `font-feature-settings: "cv11"` глобально (одноярусная «a» — спокойнее в латинских названиях: vast.ai, Grab).
- Все суммы, проценты, даты в таблицах, KPI — класс `.num` (`tabular-nums`). В заголовках и обычном тексте цифры пропорциональные.

## 3. Формат чисел и денег

Один модуль на фронте `src/lib/format.ts` (и такой же `format.py` в боте — тексты бота формирует backend/бот одинаково). Деньги приходят из API **строкой-Decimal** (`"1250000"`, `"12.40"`), фронт не делает арифметику над суммами — только форматирует. Для форматирования — `Intl.NumberFormat` поверх строки, без `parseFloat` для VND/RUB целых; для дробных — разбиение строки по точке (никакого float).

### 3.1. Правила

| Правило | Значение |
|---|---|
| Разделитель тысяч | неразрывный пробел U+00A0 (`1 250 000`) |
| Десятичный разделитель | **точка** (`12.40`, `0.0215`) — так пишут суммы в чате («1.5м», «≈ $12.40») |
| Минус | настоящий минус U+2212 `−`, не дефис |
| Плюс | `+` только у доходов и в «изменении к прошлому периоду» |
| Пробел между числом и символом | U+00A0 (`150 000 ₫`, `300 USDT`) |
| ₫ VND | суффикс, 0 знаков: `1 250 000 ₫` |
| ₽ RUB | суффикс, 0 знаков, если копеек нет, иначе 2: `4 990 ₽`, `4 990.50 ₽` |
| $ USD | префикс, всегда 2 знака: `$12.40`, `$1 250.00`, минус перед знаком: `−$180.00` |
| USDT, USDC | суффикс-тикер, 2 знака, хвостовые нули обрезаем только у целых: `+300 USDT`, `12.50 USDT` |
| Прочая крипта (TON, BTC, ETH…) | суффикс-тикер, до 8 значащих после точки, хвостовые нули убираем: `3 TON`, `0.0215 BTC` |
| Пересчёт | префикс `≈ ` (U+2248 + U+00A0): `≈ $12.40`, `≈ 312 000 ₫` |
| Курс | `1 TON ≈ $5.40`, `$1 = 26 140 ₫ (VCB, 27.10)` |
| Ноль | `0 ₫` — только когда это реальный ноль (нет расходов сегодня). Нет данных — `—` |
| Неизвестный остаток | текст «остаток не задан» `text-muted-foreground`, не число |
| Компактно (оси графиков, плитки на 390 px при нехватке места) | `1.25м ₫`, `450к ₫`, `$1.2k`. В KPI на desktop компакт не используем |

### 3.2. Примеры (эталон для тестов `format.test.ts`)

```
formatMoney("1250000", "VND")                  → "1 250 000 ₫"
formatMoney("-420000", "VND", {sign:"always"}) → "−420 000 ₫"
formatMoney("300", "USDT", {sign:"always"})    → "+300 USDT"
formatMoney("12.4", "USD", {approx:true})      → "≈ $12.40"
formatMoney("-180", "USD")                     → "−$180.00"
formatMoney("3", "TON")                        → "3 TON"
formatMoney("0.02150000", "BTC")               → "0.0215 BTC"
formatMoney("4990.5", "RUB")                   → "4 990.50 ₽"
formatCompact("1250000", "VND")                → "1.25м ₫"
formatCompact("450000", "VND")                 → "450к ₫"
formatPercent("0.183", {sign:"always"})        → "+18%"   (до 1 знака только если |x| < 10%: "+4.5%")
```

(В примерах пробелы — U+00A0.)

### 3.3. Даты и время

- Пояс всегда `Asia/Ho_Chi_Minh` из настроек пользователя, не пояс браузера.
- Относительные: «сегодня, 14:32», «вчера, 09:10», «пт, 24 окт», «24 окт 2025» (если не текущий год).
- Группы в списке операций: «Сегодня», «Вчера», «Пятница, 24 октября», с итогом дня справа: `−595 000 ₫`.
- Периоды: «Октябрь 2026», «20–26 окт», «1–27 окт». Тире — короткое `–` без пробелов в диапазонах дат.

## 5. Радиусы, тени, отступы, сетка, слои

### 5.1. Радиусы
`--radius: 12px`. Кнопки/инпуты/чипы 8, поповеры/меню 10, карточки 12, AI-строка на главной и шиты 16, окно Quick Capture 20 (Windows 11 само скругляет 8 px — делаем окно `transparent: true` и рисуем свой радиус), аватары/точки — `rounded-full`. Вложенные скругления: внутренний = внешний − отступ (карточка 12, внутренний блок с паддингом 4 → 8).

### 5.2. Тени
По умолчанию карточки **без тени**: `bg-card border border-border`. Тени — только у того, что парит:
- `shadow-xs` — нажимаемые карточки KPI в покое (почти незаметно);
- `shadow-sm` — AI-строка на главной;
- `shadow-md` — поповеры, выпадающие меню, тултипы графиков, карточка результата под AI-строкой;
- `shadow-lg` — окно Quick Capture, командная палитра, мобильные шиты, диалог.
В тёмной теме глубина передаётся светлее поверхностью (`card` → `popover`) плюс тонкой светлой обводкой внутри тени — чёрные тени на чёрном не видны.

### 5.3. Отступы
Шаг 4 px. Используем только: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- Внутри карточки: 16 (mobile), 20 (desktop). Между карточками: 12 (mobile), 16 (desktop).
- Строка операции: высота 44 (desktop) / 56 (mobile, двухстрочная), горизонтальный паддинг 12.
- Между секциями страницы: 32 (desktop), 24 (mobile).
- Боковые поля страницы: 16 (390), 24 (768), 32 (≥ 1024).

### 5.4. Сетка и брейкпоинты
- `sm 640`, `md 768`, `lg 1024`, `xl 1280`, `2xl 1440` (Tailwind по умолчанию + 1440 как основной макет).
- Desktop ≥ 1024: боковая панель 232 px (свёртывается до 64 px по `[`), контент `max-w-[1200px]` по центру, 12 колонок, гаттер 16.
- Tablet 768–1023: боковая панель свёрнута до иконок.
- Mobile < 768: без боковой панели, нижнее меню 64 px + `env(safe-area-inset-bottom)`, верхняя панель 52 px + `env(safe-area-inset-top)`.

### 5.5. Слои (z-index)
`base 0` · `sticky-header 10` · `bottom-nav 20` · `dropdown/popover 40` · `sheet/dialog 50` · `toast 60` · `offline-banner 70` · `command-palette 80`.

## 6. Материалы и глубина

- **Обычные поверхности непрозрачные.** Прозрачность — только у того, что лежит поверх контента и должно сохранять контекст.
- Верхняя панель на мобильном и sticky-шапка таблицы операций: `bg-background/80 backdrop-blur-xl backdrop-saturate-150` + нижняя граница 1 px, появляется только после прокрутки на 4 px (до этого граница прозрачная).
- Нижнее меню PWA: тот же материал, `bg-card/85`.
- Окно Quick Capture: в Windows 11 — `backgroundMaterial: 'acrylic'` (Electron ≥ 30), поверх — `bg-card/80` слой, чтобы текст оставался AA на любом фоне рабочего стола. Fallback (Windows 10, отключённая прозрачность в системе, `prefers-reduced-transparency`) — сплошной `bg-card`. Обводка окна: 1 px `oklch(1 0 0 / 0.08)` в тёмной, `oklch(0 0 0 / 0.08)` в светлой.
- Затемнение под шитом/диалогом: `bg-black/40` (светлая) и `bg-black/60` (тёмная), без блюра — блюр всей страницы на телефонах дорогой.
- `@media (prefers-reduced-transparency: reduce)` — все `/80`-материалы становятся сплошными.

## 7. Движение

Движение объясняет, откуда взялся элемент и куда он ушёл; оно никогда не заставляет ждать. Ввод не блокируется анимацией: Enter можно нажать, пока предыдущая карточка ещё въезжает.

### 7.1. Токены

| Токен | Значение | Где |
|---|---|---|
| `--dur-instant` | 80 ms | hover, нажатие (scale 0.98), смена цвета |
| `--dur-fast` | 140 ms | появление тултипа, чипа, смена вкладки |
| `--dur-base` | 200 ms | поповер, карточка результата, строка списка |
| `--dur-slow` | 320 ms | шит, окно Quick Capture, смена страницы |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | всё, что появляется |
| `--ease-in` | `cubic-bezier(0.55, 0, 1, 0.45)` | всё, что исчезает (в 0.7× длительности появления) |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | перемещение между состояниями |

Пружины (библиотека `motion`, импорт `motion/react`; стоит рядом с React без конфликтов):

```ts
export const spring = {
  snappy: { type: "spring", stiffness: 520, damping: 40, mass: 0.8 }, // карточка результата, чипы, кнопки выбора счёта
  gentle: { type: "spring", stiffness: 260, damping: 30 },            // раскрытие списков, переразмер окна Quick Capture
  sheet:  { type: "spring", stiffness: 380, damping: 38 },            // мобильные шиты, свайп-закрытие (сохраняет скорость пальца)
  number: { type: "spring", stiffness: 140, damping: 22 },            // «перекат» цифр KPI
} as const;
```

### 7.2. Хореография ключевых моментов

1. **Отправка из AI-строки.** Иконка `CornerDownLeft` → 12-px спиннер-дуга на месте (через 150 ms; если ответ пришёл быстрее, спиннер не показываем вовсе). Текст в поле становится `text-muted-foreground`, поле остаётся редактируемым.
2. **Успех.** Карточка результата появляется из-под строки: `y: -6 → 0`, `opacity 0 → 1`, `scale 0.98 → 1`, пружина `snappy`. Галочка рисуется обводкой (`pathLength 0 → 1`, 180 ms). Поле очищается в тот же кадр. Новая строка в списке «Последние» въезжает сверху с подсветкой фона `bg-primary-soft`, которая гаснет за 1.2 s. KPI «Сегодня» перекатывает цифры пружиной `number` (каждый разряд отдельно, `tabular-nums`, без смены ширины).
3. **Отмена.** Строка в списке схлопывается по высоте (`dur-base`, `ease-in`), карточка результата меняется на «Отменено · Вернуть» (кросс-фейд 140 ms), KPI откатывается.
4. **Ошибка.** Поле и карточка — горизонтальный «нет-кивок» 3 колебания по 4 px за 280 ms (только при ошибке ввода, не при ошибке сети). При сетевой ошибке — без тряски, просто карточка.
5. **Quick Capture появление.** Окно уже создано и скрыто; при показе — `opacity 0 → 1`, `y: 8 → 0` (от трея вверх; если панель задач сверху — `y: -8 → 0`), 180 ms `ease-out`. Скрытие — 120 ms `ease-in`. Фокус в поле ставится **до** анимации — печатать можно сразу.
6. **Переразмер Quick Capture** под содержимое (превью массовых изменений) — пружина `gentle`, окно растёт только вверх от трея, максимум 640 px.
7. **Смена страниц** в вебе: только кросс-фейд контента 140 ms, без сдвигов. Боковая панель и AI-строка не анимируются.
8. **Скелетоны:** мягкий «пульс» непрозрачности 0.55 ↔ 1, 1.4 s, `ease-in-out`, одновременный для всех блоков (не волна — меньше шума).

### 7.3. `prefers-reduced-motion: reduce`

- Все сдвиги, масштабы, пружины → кросс-фейд 120 ms.
- Перекат цифр KPI → мгновенная замена.
- Тряска при ошибке → нет; вместо неё рамка поля `border-destructive` на 1.2 s.
- Пульс скелетонов → статичный `bg-muted`.
- Подсветка новой строки остаётся (это цвет, не движение), но без затухания-анимации — просто снимается через 1.2 s.
- Реализация: `const reduce = useReducedMotion()` из `motion/react` + CSS `@media (prefers-reduced-motion: reduce) { *, ::before, ::after { animation-duration: 1ms !important; transition-duration: 1ms !important; } }` как страховка.

## 8. Состояния

### 8.1. Загрузка

- **Первый запуск страницы** — скелетоны той же геометрии, что и контент (плитка KPI: полоска 40% ширины 12 px + полоска 60% 28 px; строка операции: квадрат 28 + две полоски + полоска справа 72 px). Никаких спиннеров на весь экран, никакого логотипа-заставки.
- Скелетон показываем только если данные не пришли за **200 ms**; до этого — пустое место той же высоты (чтобы быстрые ответы не мигали скелетоном).
- **Повторная загрузка** (TanStack Query refetch, SSE-сигнал, фокус окна) — старые данные остаются на экране, в шапке карточки появляется 12-px `RefreshCw` с вращением, без затемнения. `placeholderData: keepPreviousData` для смены фильтров.
- Кнопки во время действия: ширина не меняется, текст сохраняется, слева появляется 14-px спиннер, кнопка `aria-busy`.

### 8.2. Пустые состояния

Пустое состояние — всегда подсказка, что написать. Иконка lucide 20 px в круге 40 px `bg-muted`, заголовок `title-3`, одна строка `text-muted-foreground`, кликабельные примеры-чипы (клик вставляет текст в AI-строку, не отправляет).

| Где | Заголовок | Текст | Чипы |
|---|---|---|---|
| Последние операции (новый пользователь) | Пока ни одной операции | Напишите, как другу: сумма и на что. | `кофе 85к` `такси 70к вчера` `получил 300 USDT от клиента` |
| Сегодня без расходов | Сегодня без трат | — | — (в плитке просто `0 ₫`) |
| Операции + фильтр, ничего не нашлось | Ничего не нашлось | Попробуйте другой период или сбросьте фильтры. | `[Сбросить фильтры]` |
| Аналитика за пустой период | За этот период нет данных | Выберите другой месяц или запишите первую операцию. | — |
| Счёт без остатка | Остаток не задан | Укажите, сколько сейчас на счёте, — дальше посчитаем сами. | `[Задать остаток]` |
| «Разобрать» пусто | Всё разобрано | Операции без счёта появятся здесь. | — |

### 8.3. Ошибки

- **Ошибка разбора** (не понял) — карточка результата «Не понял…» с вариантами, ничего не записано (см. 9.2).
- **Ошибка валидации** (сумма 0, дата в будущем больше чем на сутки, неизвестная валюта) — карточка с текстом причины и подсказкой. Формулировка: что не так + что сделать.
- **AI недоступен** — простые записи продолжают работать (их разбирает парсер), сложные получают карточку «AI сейчас недоступен» с предложением ручной формы. Тон спокойный, без «Упс!».
- **Ошибка сервера 5xx / таймаут** — «Не удалось сохранить. Ничего не записано.» + `[Повторить]`. Повтор шлёт **тот же** `Idempotency-Key` — дубль невозможен.
- **Сессия истекла (401)** — в вебе переход на экран входа с сохранением набранного текста в AI-строке (sessionStorage, try/catch); в Quick Capture — экран входа внутри окна, окно не скрывается при потере фокуса («Не скрывать окно, когда открыт диалог авторизации»).
- Страница целиком упала (React error boundary) — карточка по центру: «Что-то сломалось на этой странице» + `[Обновить]` + свёрнутые технические детали (`<details>`, моно).

### 8.4. Офлайн и связь

Сигнал связи = `navigator.onLine` **и** успешный SSE-хартбит/`GET /health` за последние 30 s. Три состояния:

| Состояние | Индикатор | Поведение |
|---|---|---|
| На связи | точка 6 px `bg-income` у логотипа (desktop) / в шапке Quick Capture, тултип «На связи · синхронизировано 14:32» | обычное |
| Переподключение (SSE оборвался < 30 s) | точка `bg-warning`, пульс | ввод разрешён, запрос уходит с ретраями (тот же ключ идемпотентности) |
| Нет связи | баннер сверху `bg-warning-soft text-warning`, `WifiOff`: «Нет связи с сервером. Записи не сохраняются.» | AI-строка остаётся активной, но Enter показывает карточку «Нет связи — не сохранено» с `[Повторить]`; текст **не стирается**. Кнопки «Изменить/Удалить» в списке — `disabled` с тултипом «Нет связи». Данные на экране помечены «данные на 14:32» |

Очереди офлайн-записей в MVP нет (автономная синхронизация необязательна). Никогда не показываем «сохранено» без ответа сервера. При восстановлении связи — баннер меняется на «Снова на связи» (`bg-income-soft`) на 2 s и пропадает, данные перезапрашиваются.

## 9. Компоненты

### 9.1. AI-строка (`<AiCommandBar>`)

Главный компонент продукта. Один и тот же на главной (desktop, mobile), в Quick Capture и в командной палитре `Ctrl+K`.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ✦  На что потратил деньги?                                   Ctrl K   ⏎  │
└──────────────────────────────────────────────────────────────────────────┘
   кофе 85к · вчера такси 70к · сколько потратил на еду за неделю?          ← подсказки (только пустое поле)
```

- Высота 52 px (главная desktop), 56 px (mobile), 48 px (Quick Capture). `textarea` с автоувеличением до 4 строк (`field-sizing: content`, fallback — JS-расчёт), радиус `xl`, `bg-card`, `shadow-sm`, 1 px `--input`. Фокус: граница `--ring` + `--shadow-focus`.
- Слева `Sparkles` 18 px `text-primary`; справа kbd-подсказка `Ctrl K` (только когда поле не в фокусе и только desktop), при наличии текста — кнопка отправки 32×32 `bg-primary text-primary-foreground rounded-md` с `CornerDownLeft`.
- Placeholder: «На что потратил деньги?». На главной под полем — 3 подсказки-ротации `text-muted-foreground small`, клик вставляет.
- `Enter` — отправить; `Shift+Enter` — новая строка; `↑` в пустом поле — вставить последний отправленный текст (для правки опечатки); `Esc` — очистить, второй `Esc` — снять фокус (в Quick Capture: `Esc` — закрыть верхний слой (меню ⋯, превью, выбор), очистить поле; затем скрыть окно. Решает страница; main скрывает окно только на `Esc`, который страница не обработала).
- Во время отправки поле **не блокируется**; повторный Enter с тем же текстом в течение запроса игнорируется (кнопка в `aria-busy`), а новый текст отправляется отдельным запросом со своим ключом.
- Ключ идемпотентности генерируется при **первом** Enter для этого текста и переиспользуется для повторов (ретрай, `[Повторить]`).
- Под строкой — стек карточек результата (максимум 3 видимых, старые сворачиваются в «ещё 2»; в Quick Capture — 1 последняя).
- Доступность: `role="combobox"` не нужен — это `textarea` с `aria-label="Запись или вопрос"`, результат объявляется через `aria-live="polite"` регион («Записано: 150 000 донгов, Еда»).

### 9.6. Графики (Recharts)

Общие правила: без 3D, без градиентной заливки, без теней. Сетка — только горизонтальные линии `--border`, пунктир `3 3`. Оси — `caption muted`, компактный формат (`450к`, `1.2м`, `$1.2k`). Подписи осей без единиц, если единица в заголовке карточки. Тултип — `bg-popover shadow-md rounded-md p-2`, `small .num`: дата, затем строки «● Расходы −420 000 ₫».

| График | Тип | Детали |
|---|---|---|
| Распределение по категориям | донат, `innerRadius 68%`, `paddingAngle 1`, сегменты с `cornerRadius 3` | в центре сумма периода `title-2 .num` + «за октябрь»; справа легенда-таблица: цвет · категория · сумма · %. Hover/клик по строке легенды подсвечивает сегмент. Клик — фильтр операций |
| Динамика доходов и расходов | сгруппированные столбцы по дням/неделям/месяцам (доход и расход рядом), `radius [4,4,0,0]`, доход `--income`, расход `--expense` 85% | линия «поток» поверх `--foreground` 1.5 px; переключатель «Дни / Недели / Месяцы» |
| Расходы по дням | столбцы `--chart-1`, сегодня — 100%, прочие 70% непрозрачности; линия среднего дневного пунктиром `--muted-foreground` с подписью «в среднем 412к» | |
| Расходы по месяцам | столбцы, текущий месяц штрихованный (`pattern`), т.к. неполный | подпись «прогноз 18.2м» при наведении |
| Сравнение периодов | горизонтальные пары столбцов по категориям (этот / прошлый), прошлый — `--muted-foreground` 40% | справа Δ в % с цветом по смыслу |
| Бизнес vs личное | стек-бар по месяцам: `chart-1` / `chart-2` | + плитки «Бизнес: доход, расход, итог» |
| Топ покупок | не график — нумерованный список 10 строк с баром-полоской пропорционально сумме | |
| Спарклайн KPI | `Area` 24 px без осей, заливка 12% цвета смысла | только desktop |

- Валюта аналитики — переключатель `₫ / $` (сегмент-контрол) в шапке страницы, по умолчанию `$`. Суммы в другой валюте пересчитываются **на backend** по курсу на дату операции; на фронте только формат.
- Анимация графиков: только при первом показе (рост столбцов 320 ms `ease-out`), при смене фильтров — без анимации (`isAnimationActive={false}` после первой отрисовки), при reduced-motion — никогда.
- Пустой график — тонкий контур осей + текст по центру «Нет данных за период».
- Доступность: у каждого графика есть `aria-label` с кратким выводом («Больше всего ушло на Еду: 32%») и кнопка `Таблица` (иконка `Table2`), переключающая график на таблицу тех же данных.

### 9.7. Прочее

- **Ручная форма** (`<ManualTxSheet>`) — открывается `N`, кнопкой «Добавить» в нижнем меню, «Вручную» в карточке ошибки. Desktop — поповер-панель справа 400 px, mobile — нижний шит. Поля: сегмент Расход/Доход/Перевод, большая сумма `display .num` с выбором валюты рядом (чипы ₫ $ USDT ₽ + «другая»), категория (сетка 4×3 иконок с подписями, частые первыми, + поиск), счёт (чипы), дата (чипы «Сегодня / Вчера / 📅»), описание. `Enter` в любом поле — сохранить. Стартовая валюта — ₫, счёт по умолчанию для валюты (₫ → Карта).
- **Тосты** (`sonner`) — снизу по центру на mobile (над нижним меню), снизу справа на desktop; только с содержанием и действием: «Удалено: 45 000 ₫ · Кофе [Вернуть]». Длительность 6 s, пауза при hover.
- **Командная палитра** `Ctrl+K` вне главной: модальный Command (shadcn) 640 px, сверху AI-строка, ниже разделы «Перейти» (страницы), «Действия» (Новая операция, Экспорт, Сменить тему), «Последние операции». Если текст похож на операцию — первая опция «Записать: кофе 85к ⏎».
- **Сегмент-контрол** (₫/$, Дни/Недели/Месяцы) — `bg-muted rounded-md p-0.5`, активный — `bg-card shadow-xs`, переключение «скользящей» подложкой (`layoutId`, пружина `snappy`).

## 11. Клавиатура

Глобально в вебе (не срабатывают, когда фокус в поле ввода, кроме `Ctrl+K` и `Esc`):

| Клавиша | Действие |
|---|---|
| `Ctrl+K` / `⌘K` | Фокус в AI-строку на главной; на других страницах — командная палитра с AI-строкой |
| `N` | Новая операция вручную (9.7) |
| `/` | Фокус в поиск операций (на «Операциях»); на других страницах — переход в «Операции» с фокусом в поиске |
| `Esc` | Закрыть верхний слой (поповер → шит → палитра); в поле — очистить, второй `Esc` — снять фокус |
| `G` затем `H` / `O` / `A` / `B` / `S` | Перейти: Главная / Операции / Аналитика / Счета (Bank) / Настройки |
| `[` | Свернуть/развернуть боковую панель |
| `?` | Шпаргалка по клавишам (поповер) |

В AI-строке: `Enter` — отправить, `Shift+Enter` — новая строка, `↑` в пустом поле — вернуть последний отправленный текст. Пока видна карточка результата и **поле пустое**: `Ctrl+Z` — Отменить операцию, `Ctrl+E` — Изменить, `1–9` — выбор счёта; когда в поле есть текст, `Ctrl+Z` — обычная отмена ввода текста. В превью: `Enter` — Применить, `Esc` — Отмена.

В списке операций: `↑/↓` или `J/K` — строка, `Enter` — правка на месте, `E` — сменить категорию, `Delete` — удалить (с тостом «Вернуть»), `Ctrl+Enter` в inline-форме — сохранить.

Quick Capture: `Ctrl+Alt+Space` (переназначается; при занятой комбинации — предупреждение в настройках «Сочетание занято другой программой») — показать/скрыть; `Esc` — скрыть (кроме превью/выбора/входа, где `Esc` закрывает их); `Ctrl+Shift+F` — Полная панель.

Подсказки клавиш — компонент `<Kbd>`: `micro .num`, `bg-muted border rounded-xs px-1`, показывать на desktop в тултипах кнопок и в подвале Quick Capture; на тач-устройствах (`@media (hover: none)`) скрыты.

  Простые записи работают: <code>ресторан 600к</code>, <code>такси 150к вчера</code>

- Ошибка сервера: `⚠️ Не удалось сохранить, ничего не записано. Попробуйте ещё раз.` `[🔁 Повторить]` (повтор — тот же ключ идемпотентности, привязанный к `update_id`/`message_id`).

- Отмена: `↩️ Отменено: 150 000 ₫ · Еда` + `[↪️ Вернуть]` (60 s).

## 13. Логотип и иконка приложения

### 13.1. Идея

Монограмма **«P»** из одной толстой скруглённой линии (стебель + замкнутая чаша — «карман») и **золотая монета**, падающая в карман справа снизу. Фон — скруглённый квадрат цвета Iris с лёгким диагональным градиентом. Читается в 16 px (трей) как «P с точкой», в 512 px — как карман с монетой. Никаких букв шрифтом — только геометрия, поэтому одинаково рендерится везде.

- Iris-градиент: `#6E60EE` → `#4A3BC6` (сверху-слева вниз-вправо). Монограмма `#FFFFFF`. Монета `#F5C451` с внутренним кольцом `#D9A12E`.
- Толщина линии = 1/8 стороны (64 из 512) — в 16 px это ровно 2 px, без мыла.
- Охранная зона: 1/8 стороны со всех сторон. Монограмма укладывается в безопасный круг маскируемой иконки (радиус 40%).
- Словесный знак «Pocket» рядом со значком — Inter 600, трекинг −0.02em, высота строчных = 0.5 высоты значка.

## 14. Словарь интерфейса (микрокопирайтинг)

Тон: коротко, на «ты» не переходим и «Вы» с большой не пишем — безличные формулировки и глаголы первого лица от имени приложения («Записал», «Изменю»). Никаких «Упс», «Успешно!», восклицательных знаков.

| Ситуация | Текст |
|---|---|
| Placeholder AI-строки | На что потратил деньги? |
| Placeholder поиска | Поиск по описанию, продавцу, сумме |
| Успех | ✓ 150 000 ₫ · Еда |
| Отменено | Отменено: 150 000 ₫ · Еда · Вернуть |
| Выбор счёта | Записал в расходы. С какого счёта? |
| Разобрать | Разобрать: 2 |
| Превью | Изменю 4 операции / Удалю 3 операции |
| Превью устарело | Превью устарело — повторите запрос |
| Не понял | Не понял, что записать |
| Не хватает суммы | «…» — не хватает суммы |
| Валюта неясна | Не знаю валюту «…». Напишите, например, «15 $» или «300 USDT» |
| AI недоступен | AI сейчас недоступен. Простые записи вида «кофе 85к» работают |

| Нет связи (карточка) | Не сохранено — нет связи |
| Связь вернулась | Снова на связи |
| Устаревшие данные | данные на 14:32 |
| Остатка нет | Остаток не задан |

## 15. Доступность и чек-лист приёмки

Доступность:
- Контраст по таблице 1.4; любые новые пары цветов проверять скриптом (OKLCH → sRGB → WCAG). Мелкий текст не красим `subtle-foreground`.
- Видимый фокус у всех интерактивных элементов (`focus-visible:ring-2 ring-ring/50 ring-offset-2 ring-offset-background`).
- Зоны касания ≥ 44×44 (mobile), ≥ 32×32 (desktop).
- `aria-live="polite"` для результатов AI и тостов; суммы для скринридера — словами валюты («150 000 донгов»), через `aria-label` на элементе суммы.
- Порядок табуляции = визуальный порядок; шиты и палитра ловят фокус (Radix), `Esc` закрывает.
- Масштаб текста до 200% без горизонтального скролла на 390 px (суммы переносятся под заголовок строки).
- `lang="ru"` на `<html>`; числа с `translate="no"`.

Чек-лист для ревью каждого экрана (отмечается в PR):
1. Есть ли путь «хоткей → ввод → Enter» без мыши? Фокус ставится сам?
2. Все суммы — `.num`, справа, с правильным знаком `−`/`+` и U+00A0?
3. Пересчитанные суммы с «≈»? Неизвестный остаток не показан нулём?
4. Скелетон той же геометрии, без мигания на быстрых ответах (< 200 ms)?
5. Пустое состояние подсказывает, что написать?
6. Ошибка говорит, что не так и что сделать, и что «ничего не записано»?
7. Офлайн: нет ни одного «сохранено» без ответа сервера, текст ввода не теряется?
8. Светлая и тёмная тема проверены (скриншоты обеих в PR)?
9. `prefers-reduced-motion` — нет сдвигов и пружин?
10. Mobile 390: нет горизонтального скролла, нижнее меню не перекрывает контент, safe-area учтена?
11. Массовые изменения идут через превью + Enter, одиночные — сразу с «Отменить»?
12. Повтор (двойной Enter, `[Повторить]`) не создаёт дубль — тот же `Idempotency-Key`?
